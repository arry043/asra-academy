# ASRA Academy — Security Review & Hardening (PHASE 14)

Version 0.1.0 · Phase 14 (SEO, Security & Performance Hardening) · Reviewed 2026-10-25

This document records what was inspected, what was found, what was changed, and what is still open. It is an **internal code and configuration review with automated tests**. It is **not** a penetration test and nothing here was verified against a production deployment. Performance figures are in [PERFORMANCE.md](./PERFORMANCE.md); SEO behaviour is in [PUBLIC-WEBSITE.md §7](./PUBLIC-WEBSITE.md).

---

## 1. Threat model (summary)

| Asset                                          | Main threats considered                                                                                                                   |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Student accounts and records (many are minors) | Credential stuffing, session theft, IDOR between students, data in search engines or shared caches, privacy of certificates               |
| Staff and administrator privileges             | Vertical escalation (student/faculty → admin), self-role changes, removal of the last Super Admin, clickjacking of admin actions          |
| Payments and enrolments                        | Forged or replayed Razorpay callbacks/webhooks, client-side price manipulation, double activation, duplicate refunds                      |
| Assessments and certificates                   | Answer tampering after deadlines, forged/duplicated certificates, verification that wrongly reports a genuine certificate as non-existent |
| Availability                                   | Request-body DoS, brute force, expensive unauthenticated endpoints                                                                        |

Authentication model (unchanged, verified): short-lived **access JWT in memory only** (sent as `Authorization: Bearer`) + **refresh token in an HttpOnly cookie** scoped to `/api/v1/auth`. Only the auth routes act on a cookie, so CSRF defence is needed — and applied — only there.

## 3. Findings

Severity reflects impact × likelihood in this application. Status: **Fixed** (code + test in this phase), **Accepted** (documented risk, no change), **Open** (needs a client decision or a later change).

| ID     | Severity | Finding                                                                                                                                                                                                                                                                                                           | Status                                                                      |
| ------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| SEC-01 | High     | **Public certificate verification never worked.** The web app requested `${NEXT_PUBLIC_API_URL}/api/v1/certificates/verify/…`, but `NEXT_PUBLIC_API_URL` already ends in `/api/v1` → `/api/v1/api/v1/…` → 404, so every genuine certificate was shown as "Certificate Not Found" (server render and search form). | Fixed — `lib/certificates.ts` uses `apiRequest`                             |
| SEC-02 | High     | **body-parser 2.3.0** (via Express) — GHSA-27r3-jxmh-p828, DoS through trailing bytes after a compressed request body. Runtime-exposed: every JSON endpoint, including unauthenticated login.                                                                                                                     | Fixed — 2.4.0 (lockfile only, within Express `^2.3.0`)                      |
| SEC-03 | Medium   | **No browser security headers on the web app**: no CSP, no frame restrictions (portals and admin actions could be framed — clickjacking), no `nosniff`, no `Referrer-Policy`.                                                                                                                                     | Fixed — `next.config.ts` + `config/deployment.ts`                           |
| SEC-04 | Medium   | **Concurrent certificate claims returned 500.** The P2002 "retry" ran inside an interactive PostgreSQL transaction, which is aborted after a unique violation; 1 of 6 parallel claims failed in the new test.                                                                                                     | Fixed — enrolment row lock (`FOR UPDATE`) + pre-insert number check         |
| SEC-05 | Medium   | **Certificate pages were indexable and put the recipient's name and course in the title/description** (search results, link previews). ## 4. Browser protections (web, PHASE 14)

Set for every route by `next.config.ts` → `buildSecurityHeaders()` (`apps/web/src/config/deployment.ts`):

| Header                       | Value                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Content-Security-Policy`    | `default-src 'self'`; scripts `'self' 'unsafe-inline' https://checkout.razorpay.com`; `connect-src 'self' <API origin> https://*.razorpay.com`; `frame-src` YouTube-nocookie, Vimeo, Razorpay; `img-src 'self' data: blob: https:`; `media-src 'self' blob: https:`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self' https://*.razorpay.com`; `frame-ancestors 'none'`; `upgrade-insecure-requests` when app and API are HTTPS |
| `X-Frame-Options`            | `DENY`                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `X-Content-Type-Options`     | `nosniff`                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `Referrer-Policy`            | `strict-origin-when-cross-origin`                                                                                                                                                                                                                                                                                                                                                                                                          |
| `Permissions-Policy`         | `camera=(), microphone=(), geolocation=(), browsing-topics=()`                                                                                                                                                                                                                                                                                                                                                                             |
| `Cross-Origin-Opener-Policy` | `same-origin-allow-popups` (Razorpay bank/UPI pop-ups keep their opener)                                                                                                                                                                                                                                                                                                                                                                   |
| `Strict-Transport-Security`  | `max-age=63072000` on HTTPS production builds only (no `includeSubDomains`/`preload`: other subdomains are not ours to pin)                                                                                                                                                                                                                                                                                                                |

The API keeps Helmet's defaults (deny-all CSP, HSTS, nosniff, frameguard, CORP) — it serves JSON only.

**When adding an integration** (a new video host, analytics, a storage CDN for media): add its origin to the matching directive in `config/deployment.ts`, or the browser will block it. Development (`next dev`) additionally allows `'unsafe-eval'` and `ws:` for React tooling and hot reload.

## 6. Deployment requirements (security-relevant)

1. **`REDIS_URL` must point at a shared Redis in production** (W-03). Without it, each API instance — and on Vercel, each function instance — counts rate limits in its own memory (the limiter logs "Rate limiter using in-memory fallback"), which weakens brute-force limits across instances.
2. **Proxy trust**: `trust proxy` is `1` in production — correct behind exactly one proxy (Vercel, Render, a single Nginx). If a CDN/WAF (e.g. Cloudflare) is placed in front of the platform, the hop count must be raised, or every client shares the proxy's IP for rate limiting.
3. **`CORS_ORIGINS`** = the production web origin(s) only; it is also the CSRF allow-list.
4. **`NEXT_PUBLIC_API_URL`** must be set at **web build time**; its origin is written into the CSP `connect-src`. A wrong value blocks API calls in the browser.
5. **`SITE_INDEXING_ENABLED=true`** only in the production web build, with `NEXT_PUBLIC_APP_URL=https://<live domain>`; the build fails otherwise.
6. Shared caches: the public catalogue (`/api/v1/courses*`) may be cached by a CDN for up to 60 s (`s-maxage=60`), the sitemap feed for 300 s. Everything else is `no-store`.

## 7. Limitations

- No penetration test, DAST scan or third-party audit was performed. No production or staging deployment was inspected (no access).
- The CSP was reviewed against the code's integrations and exercised on a local production build (PERFORMANCE.md); the Razorpay Checkout flow and YouTube/Vimeo embeds were **not** exercised end-to-end in a browser in this phase (no Razorpay test keys locally). Test these on staging before release.
- Google Meet and Resend integrations were not exercised (no credentials).
